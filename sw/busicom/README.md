# sw/busicom: Busicom 141-PF acceptance test (spec section 9, test 1)
`./sw/busicom/run.sh` downloads the commented listing from 4004.com at run time (`fetch_rom.sh`), extracts the ROM (`extract_rom.py`), runs it on `mcs4_system` with the keyboard and printer model in `busicom_tb.sv`, types the keys in `sums.keys`, and compares the printed lines with `sums.expected`. Nothing from the listing is committed; it lives in `build/`.

`sums.expected` comes from the arithmetic (18 + 42 = 60; 100 + 35 - = 65 on an adding machine, where `-` subtracts the number just typed; 12 x 12 = 144) and the printer drum table in the listing (section 3.3: `+ - X =` in column 17, the total marker `*` in column 18). The line `0C` also comes from the listing: its button table (line 555) gives the C key `fpar` = b (= 11) and `WR=0`; `fpar` is the drum sector of the printed symbol, and sector 11, column 17 is `C` (section 3.3). So a clear prints the number 0 and the symbol C.
